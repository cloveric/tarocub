# Telegram Instance Agent Instructions

TaroCub keeps Telegram instructions in two separate layers:

- Stable channel rules are bridge-owned, generated by `src/telegram/agent-instructions.ts`, and injected at runtime on every turn.
- Instance `~/.cctb/<instance>/agent.md` is user-owned and contains only the bot's persona, language, tone, and durable preferences.

New instances create an empty `agent.md` during `telegram configure` or `telegram access pair`. The file is never populated with bridge transport syntax. Edit it only when an instance needs a distinct personality or durable user preference.

Do not put file-delivery tags, cron schemas, web-routing rules, request-scoped paths, request ids, or side-channel tokens in `agent.md`, resumed project `AGENTS.md`, or `CLAUDE.md`. The bridge supplies those rules independently of the selected engine, so Codex, Claude, Kimi, DeepSeek, and Antigravity receive the same channel contract without duplicating it in user configuration.

Request-scoped `.telegram-out/<requestId>/` directories are runtime output buffers and are pruned after 24 hours.

Migrate existing instances after pulling a release that adopts runtime-managed Telegram instructions:

```bash
telegram instructions migrate --all --dry-run
telegram instructions migrate --all
```

The migration removes only known generated or legacy `## Telegram Transport` blocks while preserving persona text. A custom transport section is reported for manual review and left unchanged by default. An explicit `--force` removes a custom transport section after creating an adjacent `agent.md.bak.<timestamp>` backup.

The old `telegram instructions upgrade` spelling remains as a compatibility alias, but new operator guidance should use `migrate`.
